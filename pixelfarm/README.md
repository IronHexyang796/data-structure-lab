# 像素农场 · PIXEL FARM

《数据结构与算法》课程实验工程。

十次实验，一层层把这块 6×6 的荒地，做成一个能玩、能算账、有网页版的农场。

---

## 三分钟开始（VSCode）

**只需要四步。全程不用装 make，不用敲 gcc。**

1. **解压到固定位置**，例如 `D:\ds\pixelfarm\`。
   <br>不要放桌面、U 盘、OneDrive；**路径里不能有中文和空格**。

2. **VSCode → 文件 → 打开文件夹 → 选 `pixelfarm` 这一层**（不是打开某个 .c 文件）。
   左侧应该能看到 `engine`、`include`、`src`、`tests`、`.vscode` 这一整棵树。

3. **按 `Ctrl + Shift + B`** —— 编译。底部会弹出一行 `[OK] farm.exe is ready.`

4. **按 `F5`** —— 运行。会弹出一个黑窗口，那就是游戏。
   方向键移动，`T` 开垦，`S` 播种，`W` 浇水，`H` 收获，`?` 看帮助，`Q` 退出。

> 第一次编译如果报 `gcc not found`，是编译器还没装好：看《环境与集成手册》第 02 章。
> 按 F5 如果报 `gdb.exe` 找不到，不影响：用 `Ctrl+Shift+B` 编译，然后在终端里敲 `pf run`。

### 每周只做一件事

```
把 templates\field.c  复制一份  →  src\field.c  →  照着任务书改
```

`src\` 是**你唯一要动的目录**。别的文件一个都不要改。

## 这个工程是怎么组织的

```
pixelfarm/
├── .vscode/          编辑器配置（任务、运行、编码）。已经配好，不用动
├── include/          头文件。老师提供，禁止修改
├── engine/           引擎：渲染、键盘、时钟、存档、主循环。老师提供，禁止修改
├── src/              ★ 你写的代码全在这里
│   ├── stub.c        临时实现（能跑但很笨）。老师给的，不要动
│   └── field.c …     你每周新建一个，从 templates/ 复制
├── templates/        每周的起始模板（先复制到 src/ 再改）
├── tests/            自动测试。老师提供，禁止修改
├── data/crops.csv    作物数据。老师提供
├── docs/             实验报告模板 + 环境问题速查
├── web/              网页版（基础版用不到，第 3 周起可选）
├── sql/              数据库脚本（选做，第 10 周）
├── tools/            性能对比脚本（第 9 周）
├── save/             存档
├── pf.bat            一键脚本（Windows）
└── pf                一键脚本（macOS / Linux / WSL）
```

**一句话规则：只改 `src/` 和 `docs/`，别的地方一个字都不要动。**

## 常用命令

在 VSCode 里按 `Ctrl + ` ` 打开终端（终端已经在工程根目录），然后敲：

| 命令 | 干什么 |
|---|---|
| `pf` | 编译。要求 0 个 warning |
| `pf run` | 编译并进游戏 |
| `pf test` | 跑全部测试 |
| `pf test 3` | 只跑第 3 周那套 |
| `pf demo` | 自动玩 30 天，出一份报告 |
| `pf bench` | 七种排序的性能对比（第 9 周） |
| `pf json` | 把当前状态导出成 `web/data.json` |
| `pf serve` | 启动网页服务器 → 浏览器开 `localhost:8080` |
| `pf clean` | 清掉编译产物。出怪问题先敲这个 |
| `pf help` | 把上面这些再列一遍 |

这些按钮背后跑的就是上面这些命令，不想敲命令也可以：

| 在哪里点 | 等于 |
|---|---|
| `Ctrl + Shift + B` | `pf` |
| `F5` / 左侧「运行和调试」 | `pf run` |
| `Ctrl + Shift + P` → 输入「运行任务」 | 全部任务都在里面 |

> macOS / Linux / WSL 上把 `pf` 写成 `./pf`。

## 最重要的一件事：时间就是你的算法

屏幕上方有个「计算已耗」。它不是装饰，是你自己代码的代价：

- **1 次比较 = 0.05 秒游戏时间**
- **1 次移动（挪数据）= 0.10 秒**
- **1 次 malloc = 2 秒**

一天只有 24 小时。你写的排序越慢，按 `M` 看行情时掉的时间越多，能收的菜就越少。

第 1 周的仓库是「线性扫描」，第 2 周的链表是「一个个跳」，第 9 周的排序如果还用冒泡——
**这些都会实实在在地吃掉你的游戏时间。** 这不是比喻，数字就在屏幕上。

## 关于 stub.c 和 templates/

`src/stub.c` 里每个模块都有一段「临时实现」。它们能跑，但用的是最笨的办法：
定长数组 + 线性扫描，该 O(log n) 的地方是 O(n)，该用堆的地方在排序。

**这不是给你抄的，是给你对比的。**

你只要在 `src/` 下建一个 `field.c`，编译脚本就会自动让 stub 里第 1 周那段失效
（`pf` 会打印「done: field」和「still stub: growth undo ...」，一眼看得出进度）。

所以：**从 `templates/` 复制，不要从空文件开始写。**
`templates/field.c` 里 14 个函数都是齐的，函数体是空的（返回 `PF_PARAM`），
一复制过来就能编译通过，然后你一个一个把 TODO 填掉。

## 出问题了

1. **先 `pf clean` 再 `pf`**，一半的怪问题这样就没了
2. **看报错的第一条**，后面的常常是连锁反应
3. **查 `docs/环境问题.md`**（20 条常见报错对照）
4. 还不行，把**报错原文**贴给 AI，问「这条报错是什么意思」，而不是「怎么改」
