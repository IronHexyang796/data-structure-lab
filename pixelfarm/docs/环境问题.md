# 环境问题速查

> 90% 的问题在前两节。按顺序试，别跳。

## 零、卡住了先做这三件事

1. **`pf clean` 再 `pf`** —— 编译产物坏了，清一次就好，这招能解决一半怪问题。
2. **从上往下读第一条 error** —— 后面几十条常常是第一条的连锁反应，改第一条就够了。
3. **确认终端在工程根目录** —— 终端提示符应该是 `...\pixelfarm>`，不是 `...\pixelfarm\src>`。

---

## 一、VSCode 里的问题

### 按 `Ctrl+Shift+B` 没反应 / 提示"没有生成任务"

说明 VSCode 没读到 `.vscode/tasks.json`。三种可能：

1. **你打开的是单个文件，不是文件夹** —— 文件 → 打开文件夹 → 选 `pixelfarm` 这一层。
   左上角文件名旁边应该显示 `PIXEL FARM` 或文件夹名，不是 `field.c`。
2. **解压时 `.vscode` 这个目录被丢了** —— 有些解压软件会跳过以点开头的文件夹。
   重新解压一次；实在没有，手动在 `pixelfarm` 下建 `.vscode` 文件夹，把包里的三个 json 放进去。
3. **VSCode 打开的是上一层目录** —— 你选的必须是 `pixelfarm`（里面有 `src`、`engine` 的那一层）。

### 终端打开后不在工程根目录

`Ctrl + ` ` 打开终端，提示符应该是 `D:\ds\pixelfarm>`。
如果显示 `C:\Users\你的名字>`，说明你只打开了单个文件，回到上一条。
如果是 `...\pixelfarm\src>`，敲两次 `cd ..` 退回来（或者关掉终端重新开一个，工程已经配好默认目录了）。

### 左侧 `#include "field.h"` 全是红波浪线，但能编译

只是编辑器的"智能提示"没配好，**不影响编译**。
`.vscode/c_cpp_properties.json` 里已经写了 `includePath`；还红的话，按 `Ctrl+Shift+P` → 输入 `Reload Window` 回车。

### 按 F5 报"找不到 gdb.exe"或"无法启动程序"

**不影响你做实验。** 用这两步代替：

```
Ctrl + Shift + B     编译
pf run               运行
```

想用断点调试再装 gdb（MinGW 一般都带，在 `...\bin\gdb.exe`）。

### 中文变成 `鍧楀湴` 这种乱码

- 游戏和测试程序自己会把控制台切成 UTF-8，正常不会乱。
- 如果你自己 `printf` 了中文出现乱码：在终端里敲一次 `chcp 65001` 就好。
- 源文件本身必须是 UTF-8：VSCode 右下角显示的应该是 `UTF-8`，不是 `GBK` 或 `UTF-8 with BOM`。

## 二、编译不过

### `gcc` 提示"不是内部或外部命令"

PATH 没配，或者配完没重启。

1. 关掉**所有**终端和 VSCode
2. 重开一个终端，敲 `gcc -v` 看有没有版本号
3. 还没有 → 检查 PATH 里加的是不是 `...\bin`（不是 `...\w64devkit`）
4. 具体装法见《环境与集成手册》第 02 章

### `fatal error: field.h: No such file or directory`

编译时没加 `-Iinclude`。用 `pf` 就不会有这个问题；手敲 gcc 要写 `gcc -Iinclude -Iengine ...`。

### `undefined reference to 'barn_grow'`

**链接阶段**找不到某个函数的实现。90% 是这一种：

> 你建了 `src/field.c`，但里面**没有把 14 个函数写全**。
> 因为 `src/field.c` 一出现，`src/stub.c` 里第 1 周的临时实现就自动失效了，
> 那 14 个函数就全得由你提供。

怎么办：把 `templates/field.c` 复制过来（函数是齐的），再把你的代码搬进去。
或者先把缺的那个函数补一个空壳 `{ return PF_PARAM; }`。

### `multiple definition of 'barn_grow'`

同一个函数被定义了两次。绝大多数是：**你自己又写了一遍模板里"老师给的"那段**。
比如 `market.c` 里的 `g_stat`、`cmp_price`，`road.c` 里的 `graph_load_default`——这些不要重写。

更少见的一种：文件建在了 `src/` 外面，或者建成了 `src/field.C`（大小写/扩展名不对）。

### `Permission denied` / `cannot open output file farm.exe`

上一版程序还在跑。**在那个黑窗口里按 `Q` 退出**，或者任务管理器结束 `farm.exe`。
`pf` 编译前会提醒你一次。

### 一堆 `warning`，但编译过了

课程要求 **0 warning**。常见三种：
- 变量定义了没用 → 删掉，或者 `(void)变量;`
- `printf` 的格式串和参数类型对不上 → `%d` 配 `int`，`%ld` 配 `long`，`%s` 配 `char *`
- 函数声明了没实现 → 见上面的 `undefined reference`

## 三、能编译，但一跑就崩

### 什么都不打印就退出 / "程序已停止工作"

空指针。用 gdb 三步定位：

```
gdb farm.exe
(gdb) run
(gdb) bt            # 崩在哪一行、谁调用的
(gdb) p 变量名       # 打印变量
```

在 VSCode 里：装好 gdb 后直接按 F5，会在崩的那一行停住，左边能看到所有变量。

### 段错误（Segmentation fault / 0xC0000005）

常见四种：
1. `p->next` 但 `p` 是 NULL
2. 数组越界（`plot_at(-1, 0)` 忘了判越界）
3. `free` 之后又用
4. 结构体没初始化就 `free` 里面的指针（`SparseMat m; free(m.data)` —— `m.data` 是垃圾值）

### 数字全是 3735928559 之类

用了没初始化的变量。`calloc` 代替 `malloc` 可以先排除这一种。

### 中文输出一半乱码一半正常

控制台代码页被别的程序改了。关掉终端重开，或者敲 `chcp 65001`。

### 画面疯狂闪烁

用 `pf run` 在**真正的终端**里跑，别双击 exe。

### 键盘按了没反应

用 VSCode 的终端，或者 F5 弹出的黑窗口。某些精简终端不支持非阻塞读键，方向键会失灵。

## 四、测试相关

### 跑测试全是 `[FAIL]`

刚把模板复制过来时**本来就全是红的**——函数体还是空的。这不是错误，是你还没开始写。

### 测试程序编不过

`pf test 1` 会先编译 `tests/t01_field.c`。它和游戏用的是同一批 `src/*.c`，
所以你的代码编不过时，测试也编不过。先把 error 改掉。

### `no such file: tests\t0X_*.c`

周次写错了。第 1 周是 `pf test 1`，第 10 周是 `pf test 10`，没有第 11 周。

### `[slow]` 是什么

**不算失败**，是"能跑通但比合格线慢很多"。说明你的数据结构选对了、实现还不够好
（比如该 O(log n) 的地方还是 O(n)）。第 9 周会看到很多。

## 五、网页版和数据库（选做，基础版用不到）

### 浏览器打开一片空白，控制台报 `CORS policy`

你直接双击了 `index.html`。必须用 `http://` 访问：

```
pf serve            # 然后浏览器开 http://localhost:8080
```

### `端口 8080 被占用`

换个端口：`farm.exe --serve 8081`。

### 页面能开，但数据一直是 0

`web/data.json` 没生成。先跑一次 `pf json`。程序的工作目录必须是 `pixelfarm/` 这一层。

### `mysql.h: No such file or directory`

Connector/C 的 `-I` 路径不对。路径里有空格**必须整个用双引号包起来**。
详见《环境与集成手册》第 10 章。

## 六、还是搞不定

按这个顺序：

1. `pf clean` 再来一次
2. 把**完整的报错原文**（文字，不是截图）复制出来
3. 贴给 AI，问「这条报错是什么意思」，**别问「怎么改」** —— 问"什么意思"，它解释完你自己就知道怎么改了
4. 还不行，带着报错原文找老师或同学
